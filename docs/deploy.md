# Deployment

FIRMS Harmonizer deploys as a single Docker container that serves the FastAPI backend and
the built React frontend from the same origin. The recommended setup costs nothing and
needs no credit card.

## Recommended stack

| Piece | Service | Free allowance | Role |
| --- | --- | --- | --- |
| App hosting | Hugging Face Spaces, Docker SDK, CPU basic | 2 vCPU, 16 GB RAM, 50 GB disk; sleeps after 48 h without visitors | Builds `Dockerfile` and serves the app at `https://<user>-<space>.hf.space` |
| Runtime data | Hugging Face dataset repository | Free public or private storage | Holds the cube, accepted detections and ignored lookup tables (about 90 MB) |
| Continuous deployment | GitHub Actions | 2,000 minutes per month on private repositories | Redeploys the Space after the `Verify` workflow passes on `main` |
| Fire Copilot model (optional) | Google AI Studio (Gemini) or Groq | Free tiers with rate limits | Online answers; without a key the Copilot answers from local data only |
| Live FIRMS sync (optional) | NASA FIRMS map key | Free | Needed only for the "Update through today" button |

### Why this stack

- **One container, one origin.** The API and frontend share a URL, so there is no CORS
  configuration and no second service to keep in step.
- **Enough memory.** DuckDB, SciPy and the risk model hold the regional series in memory.
  The 16 GB of a free Space is ample; 512 MB free tiers (Render, Koyeb) are not.
- **No credit card.** Google Cloud Run's free tier would also work with this `Dockerfile`
  (it reads the `PORT` variable), but it requires a billing account. Fly.io and Railway no
  longer have permanent free plans. Vercel, Netlify and Cloudflare cannot run this Python
  backend within their serverless limits.
- **Data outside git.** Runtime data is regenerated by the pipeline, so it lives in a
  dataset and is downloaded when the container starts, instead of bloating the repository.

### Trade-offs

- A sleeping Space takes about a minute to wake on the first visit.
- Free Spaces have no persistent disk: the "Update through today" sync cannot keep new
  data across restarts. Publish a new dataset version instead (see below).
- The Space and dataset are public by default. Private works too; the Space then needs an
  `HF_TOKEN` secret with read access to the dataset.

## One-time setup

From the repository root, with the project virtual environment:

1. Create a free account at <https://huggingface.co/join> and a **write** access token at
   <https://huggingface.co/settings/tokens>.
2. Log in once on this machine (the token is stored by `huggingface_hub`, never in git):

   ```powershell
   firms-harmonizer\.venv\Scripts\python -m pip install -r deploy\requirements.txt
   firms-harmonizer\.venv\Scripts\hf auth login
   ```

3. Publish the runtime data (requires the real cube built by `python scripts/run_pipeline.py etl`):

   ```powershell
   firms-harmonizer\.venv\Scripts\python deploy\publish.py data --repo <user>/firms-harmonizer-data
   ```

4. Create and deploy the Space, and wait for it to report healthy:

   ```powershell
   firms-harmonizer\.venv\Scripts\python deploy\publish.py space --repo <user>/firms-harmonizer --data-repo <user>/firms-harmonizer-data --wait
   ```

   To enable the online Copilot or live sync, set `GEMINI_API_KEY` (or `GROQ_API_KEY`),
   `TAVILY_API_KEY` and `FIRMS_MAP_KEY` in the shell and add `--secrets-from-env`. They are
   stored as Space secrets; they are never printed or committed.

5. Enable automatic redeploys in GitHub: under **Settings → Secrets and variables →
   Actions**, add the secret `HF_TOKEN` (a write token) and the variables `HF_SPACE`
   (`<user>/firms-harmonizer`) and `HF_DATA_REPO` (`<user>/firms-harmonizer-data`).

## Updating

- **Code:** merge to `main`. When `Verify` passes, `.github/workflows/deploy-space.yml`
  uploads the git-tracked source to the Space, which rebuilds. It can also be run manually
  from the Actions tab.
- **Data:** rebuild the cube locally, run step 3 again, then restart the Space from its
  settings page (or redeploy). The app restores the original file timestamps from
  `manifest.json` so cache keys stay consistent.
- **Status:** `python deploy\publish.py status --repo <user>/firms-harmonizer`.

## Running the container locally

```powershell
docker build -t firms-harmonizer .
docker run -p 7860:7860 -e DATA_REPO=<user>/firms-harmonizer-data firms-harmonizer
```

Instead of `DATA_REPO`, mount a local `firms-harmonizer\data\processed` folder at
`/app/data/processed`. Then open <http://localhost:7860>.

## Configuration reference

| Variable | Default | Meaning |
| --- | --- | --- |
| `DATA_REPO` | unset | Hugging Face dataset downloaded into `data/` at start-up |
| `DATA_REVISION` | latest | Dataset branch, tag or commit to pin |
| `HF_TOKEN` | unset | Needed only for a private dataset |
| `COPILOT_OFFLINE` | `1` | `0` enables online model and search providers when a key is set |
| `COPILOT_PROVIDER` | `groq` | `gemini` or `groq` |
| `NRT_POLLING` | `0` | Background FIRMS polling; keep off on free hosting |
| `USE_SYNTHETIC_CUBE` | `0` | `1` serves the labelled synthetic demo cube instead of real data |
| `PORT` | `7860` | Listening port |
| `REQUEST_RATE_MULTIPLIER` | `1` | Scales the per-visitor request limits |

Without a real cube the container exits with an explanation rather than serving synthetic
data silently. Each visitor gets their own rate-limit bucket because the server trusts the
platform's forwarded client address.
